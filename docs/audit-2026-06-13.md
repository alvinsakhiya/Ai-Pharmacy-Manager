# Engineering Audit — 13 June 2026

## Scope

The audit covered the React frontend, Django REST API, PostgreSQL models and queries, RBAC,
patient/dosette/stock workflows, forecasting, accessibility, tests, documentation and Docker
deployment. Changes were kept incremental and aligned with the existing architecture.

## Issues Addressed

- The full patient list was available to every authenticated role despite the administrator-only
  product rule. Listing is now administrator-only; all staff retain a limited search endpoint.
- Notification CRUD allowed arbitrary client-created or deleted system alerts. Notifications are
  now read-only records, with refresh restricted to pharmacists and administrators.
- Dosette schedules accepted unknown days/slots, zero doses and duplicate medicines.
- Dashboard, forecasting, picking and notification paths repeated stock aggregation queries.
- Invalid stock-trend query parameters could produce server errors.
- Important account, medicine, supplier, batch, dosette and picking changes were not consistently
  written to the audit log.
- Login attempts had no dedicated API throttle.
- Shared modals did not trap/restore focus or expose an accessible title.
- Sortable tables and clickable rows were mouse-oriented; mobile navigation was missing.
- Several status and dosette visuals relied too heavily on colour, and a picking checkbox had no
  accessible name.
- AI showcase failures silently fell back to sample data and some copy implied live data.
- OpenAPI generation reported operation and enum conflicts.
- Frontend lint warnings, unused starter assets and a leftover local SQLite database caused noise.
- Setup documentation lacked a database dashboard and did not clearly separate live API features
  from simulated portfolio workflows.

## Improvements Made

- Added role-scoped patient search, query validation, annotated dosette counts and patient API tests.
- Added strict dosette schedule validation and regression tests.
- Made notifications immutable through normal CRUD and added permission tests.
- Added stock aggregate annotations and reused them across dashboard, reports, forecasting,
  notifications and picking generation.
- Added bounded report query serializers and complete OpenAPI annotations.
- Expanded audit logging and added a configurable login throttle.
- Added mobile navigation, keyboard-operable tables/cards, accessible modal focus management,
  named controls and non-colour status cues.
- Added explicit live/simulated AI source notices and retained human-review warnings.
- Added Vitest/Testing Library coverage for shared table and modal interactions.
- Added PostgreSQL 18 and pgAdmin to the one-command Docker stack; SQLite is unsupported.
- Updated setup, deployment, architecture and testing documentation.

## Known Limitations

- The top-bar rich patient record, medication dispense history and admin patient gallery still use
  browser fixtures. PostgreSQL has patient demographics and notes, but needs medication-history
  models/endpoints and frontend integration.
- AI safety, intake, daily-brief and co-pilot screens use deterministic academic logic because
  `/api/ai/*` endpoints do not yet exist. Backend stock forecasting is live and PostgreSQL-backed.
- JWTs are stored in browser local storage. A production deployment should prefer short-lived
  access tokens with refresh tokens in secure, HttpOnly, SameSite cookies.
- Settings actions for profile/password/session management are demonstration surfaces.
- Redis is provisioned but background forecasting and notification jobs are not yet scheduled.
- Browser end-to-end tests, automated accessibility scanning and CI/CD are not yet configured.

## Recommended Priorities

1. Build medication, dispense-event and patient-history APIs, then remove patient browser fixtures.
2. Implement server-side AI orchestration against PostgreSQL with evaluation metrics and
   pharmacist approval records; keep deterministic fallbacks for demos only.
3. Move refresh authentication to secure cookies and add account lockout/monitoring controls.
4. Add Playwright journeys, axe accessibility checks and GitHub Actions quality gates.
5. Add scheduled jobs, PostgreSQL backup/restore drills and production observability.
